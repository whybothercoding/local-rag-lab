The big picture

For dummies: two jobs. First the system reads your documents and files them away (ingest). Then, for each question, it fetches the right filed pieces, writes an answer and double-checks it (ask). Security wraps both.

For dummies, the buzzword: this is a compound AI system. Not one giant brain, but a team of small specialists wired together, each doing one job you can test on its own.

The pipeline, step by step

For dummies: follow the arrows. Solid arrows are the normal route. Dashed pink arrows are loops: "that wasn't good enough, try again". Red arrows stop or hand over to a person.

One question, three forms

The state carries your text three ways on purpose. asked_question is exactly what you typed, with personal data masked, for the reviewer and the audit log. original_question is the standalone version (follow-ups expanded) used for the cache key, retrieval and grading. sanitized_question is the search query, which the rewrite loop is allowed to change.

Five journeys through the graph

The same graph produces very different trips. Each chip is a node; the pink tag is the route taken out of it.

1. A planted order

For dummies: someone types "ignore your rules". The bouncer stops them at the door.

  1. guardrail fail
  2. END

Nothing is searched. The reply is [SECURITY VIOLATION: Adversarial prompt injection detected.] and the event is logged.

2. Someone already asked

For dummies: the answer is already in the notebook, so no work is needed.

  1. guardrail pass
  2. contextualize
  3. cache_lookup hit
  4. END

Only approved answers are cached, in the asker's clearance partition. Users without auto-release read reviewed entries only.

3. A normal question

For dummies: look it up, write it, check it twice, hand it over.

  1. guardrail
  2. contextualize
  3. cache_lookup miss
  4. router rag
  5. retrieve
  6. sanitize_context
  7. grade_docs approved
  8. generate
  9. grade_hallucination grounded
  10. grade_relevance relevant
  11. human_approval
  12. END

At human_approval the answer is released at once for accounts with auto-release, or frozen for a reviewer in team mode.

4. The shelves have nothing

For dummies: try twice with new words, then honestly say "I don't know".

  1. retrieve
  2. grade_docs rewrite
  3. rewrite
  4. retrieve
  5. grade_docs rewrite
  6. rewrite
  7. retrieve
  8. grade_docs circuit_break
  9. generate
  10. grade_hallucination
  11. grade_relevance
  12. human_approval

With no documents the writer returns the exact abstain sentence "I could not find relevant documentation in this workspace to answer your query." Abstentions are never cached. If the search was degraded (for example an index built by another model), the abstention waits for a reviewer like any other answer.

5. The draft contains a bad fact

For dummies: the fact-checker sends it back with a note. If it is still wrong, a human takes over.

  1. generate
  2. grade_hallucination retry
  3. generate
  4. grade_hallucination circuit_break
  5. human_approval

The reviewer sees the draft, its citations and the reason, for example a figure the sources do not contain. Auto-release is withheld even for trusted accounts.

Two ladders worth memorizing

Anatomy of a search

For dummies: cast a wide net, then keep narrowing until only the best three pages remain.

Candidates5 vectors + 5 BM25 + GraphRAG multi-hop entity traversal, filtered by clearance (widths configurable)
RRF FusionReciprocal rank fusion merges dense, sparse, and graph hops
≤ 8 cleanPieces with planted-instruction patterns are dropped
3 rerankedCross-encoder reads question and piece together, preserving graph bridges
Evidence gateBest reranker score ≥ −4.5 (default profile) or nothing moves on

Anatomy of an answer check

For dummies: cheap, strict checks first; the smarter model only for what is left.

1 · figuresAny number in the answer that the sources lack rejects it at once
2 · sentencesEach sentence needs entailment ≥ 0.7 from a source sentence (NLI, full precision)
3 · relevanceThe answer must address the question that was asked
4 · release ruleAuto-release only with auto_approve, every check passed and no blocking degradation. Else a person decides.

Who may see and do what

For dummies: two separate dials. Your role says what you may do (ask, review, release). Your clearance says how secret the pages you may see can be. Neither one grants the other.

How a permission is looked up

  1. The account's own grant on this workspace.
    Most specific wins.
  2. The account's grant on all workspaces.
    An empty list means deny.
  3. The account's groups.
    Combined, but any group's none wins.
  4. The account's own role.
  5. The default role.
    trusted on a fresh install (open mode), member after make team-mode.

Design lessons baked into the code

For dummies: these are the mistakes this project already made and measured, so you do not have to repeat them.

  1. A grader that changes with the CPU is not a grader.The int8 NLI model scored one true sentence 0.93 on Apple silicon and 0.12 on x86. Full-precision weights agreed to under 0.0001, so NLI is pinned in fp32 and a test refuses quantized weights.
  2. Run cheap exact checks before the clever model.NLI is weak at numbers (a changed figure scored up to 0.997), so invented figures are rejected by plain comparison first.
  3. Never retry an identical prompt at temperature 0.It repeats the same answer. The regeneration carries the grader's reason, and the extractive fallback is not retried at all.
  4. Give every loop its own budget.Search retries (2) and write retries (1) are separate so one loop cannot spend the other's allowance.
  5. The index proposes, the store decides.The cache index only offers candidates. The winning row is re-read, unsealed, re-checked and its cosine recomputed before it answers.
  6. Filter on the server, then guard again.Clearance is filtered inside each store and a fail-closed guard in the base class drops any hit without a valid tag, so a new adapter cannot skip it.
  7. Calibrate per model and favor the miss.Scores live on different rulers, so each profile has its own pass marks, set above the highest wrong-class score. A false accept costs more than a missed answer.
  8. Fall back out loud.Every degraded path is labelled in the answer, make status shows [!!] DEGRADED, and the serious ones force human review.
  9. Measure before building.An Ollama embedding path was removed after it failed the multilingual gates and ran 2.5x slower. A native chunker was skipped because chunking took 0.05 s of a 91 s ingest.
